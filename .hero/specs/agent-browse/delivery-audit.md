## Audit notes
- The ledger table marks AC-17 and AC-18 as `done` although the spec's Validation section asks for a fresh agent session. They're downgraded to `~` rather than `✗` because the plugin behavior has live evidence and the gap is disclosed. Recommend one cold-session run of each prompt before relying on the skill.
- Minor test gap: Changes 3 asks that "all four agent browse methods sit before `function status()`". The test asserts only `browseClose` < `status` (`tests:901`). `browseTap` and `browseBack` ordering is implied by the slice asserts, but nothing pins `browse()`'s position. If `browse()` moved below `status()`, the credential regex (`tests:923-925`) would silently stop covering it. Non-blocking.
- Unreachable edge: `browseRowKind(null)` returns `folder`, so the IPC `browseTap` would report `started:open:<n>` while `root.browseTap` returns early without sending. Neither parser emits null rows, so this can't happen today. Non-blocking.
- `browseRowKind` mirrors `Service.qml` exactly. TuneIn: `isHeader` → header, `isTab || folder` → folder, else play. Apple: BrowseTab/tab → folder, then a truthy `mspPlayCommand` → play, else folder. The truthy tests are the same and both read `defaultAction || default_action` and `itemType`.
- The live plugin folder files (`Service.qml`, `DirectorClient.js`, `manifest.json`, `README.md`, `skills/control4/SKILL.md`) match the working tree byte for byte. Read-only live `browse` and `state` calls worked. No mutating IPC was run during this audit.
